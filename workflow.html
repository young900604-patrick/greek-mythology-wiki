Loop rationale

何時必須返回前一步？

  • 來源不足／連結失效 → 回 01，補足來源。
  • 來源未對應 Wiki → 回 03，補關聯與出處。
  • 神話角色或事件衝突 → 回 01／05，查原典，修正條目。
  • 簡報超出 Wiki 的證據 → 回 04，縮減未被證實敘述。
  • HTML 無法正常操作 → 回 06，修正模板並重新驗證。
Observed correction · QA-01

Anticleia ≠ Leda

初步整理百科摘要時，發現 S06 將奧德修斯母親寫作 Leda。對照 S08《奧德賽》第11卷後，確定應為 Anticleia，因此於 Wiki 中採用原典姓名。

檢查實際前移到：「整理教學重點」之後、「產生 HTML」之前，避免錯誤傳播到 14 頁教學內容。

此設計採「人機協作＋Python 規則驗證」。並未使用持續自主運作的 LLM Agent 框架，圖中的分支是工作流設計，而非虛構的外部 Agent 呼叫紀錄。

為什麼這樣設計？

神話來源可能互有異文，使用單一摘要容易把不同版本混為一談。以原典作為優先查核依據、每篇 Wiki 連結來源，能減少無憑據的生成結果。重複節點設在實際有錯誤風險的地方，而非無限循環。
